# TikTok 扩组导入表

这个 skill 只依赖使用者自己的 TikTok MCP、飞书 Base 和账户数据。包内不包含任何账户名、飞书表 ID、Base token、应用凭据或生产数据库。

## 开始前：收集本次输入

向请求者确认或从上下文取得：

- 广告账户名或 `accountId`。账户名必须通过 `list_accounts` 解析，不能猜 ID。
- 投放日期。默认是账户时区的下一个自然日；若请求者指定日期，按指定日期使用。
- 品库所在飞书 Base，以及按账户命名的品库表；品库至少包含 `编码`、`品名`、`年龄`、`性别`、`url`。
- 素材源代码库所在表，以及其中的 `编码`、`代码合集` 字段。源库表 ID 可以由请求者提供，也可以先用脚本列出 Base 内的表再按表名选择。
- MCP 是否可以读取全部系列、已关停系列和广告组。缺少任何一份就停止，不要用猜测补齐。

飞书读取脚本需要自己的凭据文件。凭据只从本机路径或命令行参数读取，绝不写入 skill：

```bash
python scripts/feishu_read.py --credentials <自己的凭据.json> --base <自己的baseToken> --list-tables
python scripts/feishu_read.py --credentials <自己的凭据.json> --base <自己的baseToken> --table <品库tableId> --fields 品名 编码 年龄 性别 url
python scripts/feishu_read.py --credentials <自己的凭据.json> --base <自己的baseToken> --table <源库tableId> --fields 编码 爆款产品 代码合集
```

也可以设置 `FEISHU_CREDENTIALS`，这样不用重复传 `--credentials`。脚本会完整分页，并把飞书富字段压成可比较的文本；需要按字段值判断时必须使用它的默认扁平输出，不要直接比较 `--raw` 结果。

## 前置检查

1. 用任意目标账户调用 `list_campaigns(accountId, verdict="stopped")`。如果 MCP 报未知参数，立即停止并说明客户端版本过旧；没有已关停系列会静默漏掉需要重扩的品。
2. 读取账户的在投系列数。TikTok 单个广告账户最多 200 条在投系列；本批需要新建的系列数不得超过 `200 - 当前在投数`。超过时只输出超额清单，不提交创建。
3. 用 `--list-tables` 现查表名和 `table_id`。不要把 table ID 写进 skill，也不要因为某张表名相似就替代目标账户的品库。
4. 品库是只读输入。不要调用写飞书的脚本修改、补行或删除行；缺数据要点名给请求者。

## 核心流程

### 1. 以品库为外层遍历

先读完整品库，按 `编码 + 品名` 去重。不要从账户系列反向凑名单：品库中保留但账户系列全部关停的品，正是需要重扩的品。品库去重后的行数应成为最终导入表行数的基准。

对带 `-1`、`-2` 等分组后缀的编码，剥离末尾数字后缀得到根编码；同一根编码的所有品库行共享同一个系列判定，但每行仍对应一个广告组。

### 2. 读取账户快照

读取三份数据：

```text
list_campaigns(accountId, verdict="all")
list_campaigns(accountId, verdict="stopped")
list_ad_groups(accountId)
```

只判每个根编码对应的最新系列。若 MCP 输出被截断，改用使用者明确授权的本地只读数据库或分页接口拿全量数据；不能把截断结果当完整账户。

系列匹配优先使用品库编码集合，按长度降序做最长前缀匹配；不要用贪婪正则猜编码长度。仍无法匹配时，可比较去掉编码前缀后的品名，但不能因此跳过该品。

### 3. 判定

对品库中的每个根编码命中以下规则之一：

| 条件 | 结果 | 导入表系列名 |
|---|---|---|
| 最新系列累计转化达到本次配置的扩组阈值 | 可扩组 | 原系列名，逐字照抄 |
| 累计零转化且没有在投组 | 需重扩 | 新系列名 |
| 零转化但仍有在投组 | 可扩组 | 原系列名 |
| 最新系列已关停 | 需重扩 | 新系列名 |
| 账户中不存在该根编码的系列 | 新建 | 新系列名 |
| 无法可靠归入可扩 | 需重扩 | 新系列名 |

扩组阈值必须来自请求者提供的账户规则、配置文件或当前任务输入；没有阈值时先补齐这个输入，不要把某个账户的阈值当成所有账户的默认值。“新建”与“需重扩”在表中都创建新系列，但汇报时必须分开。命中一个重扩条件就停止继续覆盖判定；同一根编码的多行不能分别判定。

### 4. 生成名称和行

系列名是导入路由：与账户已有系列逐字相同才会并入原系列。名称使用投放日期和生成时刻保证唯一：

```text
可扩系列名       = 账户中的原系列名（逐字照抄）
重扩/新建系列名  = 品库首行品名-投放日期MMDD-生成时间HHMMSS
全部广告组名    = 品库该行品名-投放日期MMDD-生成时间HHMMSS
```

后缀每行都要加。系列名和广告组名都不从编码拼接。一个根编码的多行只在首行填写系列名，后续行留空；广告组名每行都填写。

导入表七列固定为：

```text
推广系列名称 / 广告组名称 / 视频代码 / 产品 URL / 年龄 / 性别 / 编码
```

- `产品 URL`、`年龄`、`性别` 来自同一品库行；空的年龄可沿用该品上次导入值，没有就留空；性别取不到用 `不限`。
- URL 只填商品页或域名，不手拼归因参数；无法取得时留空并放入 `incomplete` 清单，不要编造。
- `编码` 只用于对账和反查，不参与任何名称生成。

### 5. 分配素材代码

在源代码库中按字面编码建立索引，同时把含 `/` 的合并编码拆成多个可查询的子编码。一个编码多行时，按源库行序与品库行序一一对应：每行最多 50 个视频代码，不能把多行合并到一个组，也不能只取第一行。

自检每个根编码的品库行数与源库行数一致；不一致就点名编码并暂停交付。超过 50 个素材时按实际行数拆组，不能假定只有两组。代码合集直接写入“视频代码”列，多个代码用源库支持的分隔格式。

### 6. 查重与交付前核验

在任何真实扩组调用前执行：

```text
check_names(accountId, campaignNames=[...], adGroupNames=[...])
```

新系列名不得撞已有系列；广告组名不得撞账户内已有组或本批次其他组。然后读回生成的 `.xlsx`，至少核验：

- `可扩 + 重扩 + 新建 = 去重后的根编码数`；
- 导入表行数 = 去重后的品库行数；
- 新建系列数不超过剩余在投配额；
- 可扩系列名确实存在于账户；
- 多行品的续行紧跟首行且根编码一致；
- 每行的代码、URL、年龄和性别来自正确的品库行；
- 待清理清单（账户在跑但品库没有的品）只报告，不删除。

使用包内 `scripts/export_template.py` 按计划 JSON 生成表。单个文件不得超过 500 行或 5000 条广告；超出时按完整品分文件，不拆开同一个品的多行。

## 真实执行边界

默认只生成并交付 `.xlsx`，不调用会花费预算的接口。只有请求者在当前对话明确要求执行，并且前置核验全部通过时，才可以调用带 `confirm=true` 的扩组接口；执行结果仍需按成功、失败、未知/待回读分别报告。未知状态不能重发同一创建请求。

## 不能做的事

- 不读取、复制或写入任何包外的凭据、账户名、Base token、表 ID 或生产数据。
- 不把某个使用者的账户清单、历史案例、阈值例外或本地路径写回本 skill。
- 不写飞书品库，不替请求者删品或关停系列。
- 不因历史命名不规范而跳过品；无法确认时落入需重扩并说明原因。
- 不把失败的实时创建当成表格生成成功，也不把未知回读状态当成可重试失败。
