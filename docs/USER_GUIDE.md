# TK Ads 自动化操作使用手册

版本：1.3.0
更新日期：2026-07-15

本手册覆盖 Windows 桌面版安装与升级、本机登录权限、多广告账户、Cookie 与官方 API 接入、自动化检测与启停、定时任务、规则配置、广告分析、消息推送和多账户投放计划。

## 1. Windows 桌面版安装与升级

1.3.0 是本地优先的 Windows x64 桌面程序，不依赖自建服务器。界面、本地 API、调度器、数据库和加密凭据库均在本机运行。

1. 双击 TK-Ads-Automation-Setup-1.3.0.exe，按安装向导完成当前 Windows 用户安装；已安装旧版本的用户可直接覆盖升级。
2. 安装器会创建桌面和开始菜单快捷方式；启动“TK Ads Automation”即可进入管理界面。
3. 首次启动先创建本机开发者账户。用户名建议使用 developer；密码至少 12 位并包含大小写字母、数字和符号。程序不会内置默认密码。
4. 完成登录后，程序会在 %APPDATA%\TK Ads Automation\data 创建 SQLite 数据库和演示广告账户。Cookie 和 Token 使用当前 Windows 用户的 DPAPI 加密保存。
5. 先进入用户管理创建广告账户，再点击该账户后的“接入”完成凭据导入和状态确认。
6. 安装新版前先关闭正在运行的软件，然后直接运行更高版本安装包；不要先卸载旧版。固定 App ID 会覆盖程序文件并保留用户数据。
7. 安装或升级后打开软件，确认版本、接入状态、自动化开关和规则配置正常。

注意事项：

- 桌面版本地 API 只监听随机的 127.0.0.1 端口，不对局域网和公网开放。
- 安装目录与用户数据目录分离，覆盖升级不会删除数据库和加密凭据；主动删除 %APPDATA% 下的数据目录会造成配置丢失。
- 当前安装包未配置商业代码签名证书，Windows 可能显示未知发布者或 SmartScreen 提示。只使用本项目生成并核对来源的安装包。
- 左上角软件总开关关闭后，后台检测、定时任务、通知和真实广告写入全部暂停；配置、历史数据和登录功能仍可使用。
- 账户自动化总开关开启后，系统默认按已启用规则自动执行；检测预览始终只读。
- 开发者仍可在源码目录执行 pnpm install 和 pnpm dev，Web 管理界面默认使用 http://127.0.0.1:5173。

## 2. Cookie 会话接入

Cookie 方案适合自有、已授权的 TikTok Ads 账户。只需复制 /adgroup/list/? 和 /ad/update_status/? 两段 cURL，粘贴到两个输入框后一次导入。

1. 使用 Chrome 正常登录 TikTok Ads Manager，并切换到目标广告账户。
2. 按 F12 打开开发者工具，进入 Network，选择 Fetch/XHR。
3. 第 1 段：在接入窗口点击复制 /adgroup/list/?，粘贴到 Network 左上角 Filter 输入框。
4. 回到 TikTok 页面进入“广告组”并刷新数据。Network 中出现请求后，选择最后一条状态成功的 /adgroup/list/? 请求。
5. 在该请求上点击鼠标右键，选择 Copy → Copy as cURL (bash)。Copy as cURL (bash) 是右键菜单中的复制选项，不是请求名称。
6. 将复制的完整 cURL 粘贴到左侧“广告组列表 cURL”输入框。
7. 第 2 段：在接入窗口点击复制 /ad/update_status/?，替换 Network Filter 中的搜索内容。
8. 进入一个广告组内的广告列表，切换任意一条测试广告的开关。选择刚出现的 POST /ad/update_status/? 请求，右键 Copy → Copy as cURL (bash)。完成后可把测试广告恢复原状态。
9. 两段均导入后，在自动化中心执行一次“检测预览”。成功状态应同步系列、广告组和广告三层；若某层为 0 或出现告警，不应对该层执行自动化判断。
10. 将第二段完整 cURL 粘贴到右侧“广告启停 cURL”输入框，点击“导入并检查”。
11. 页面会显示五个必要字段：列表查询参数、更新查询参数、自动生成的复制查询参数、CSRF Token 和 Cookie。五项全部获取且账户读取正常、三级启停模板建立后，实时状态才显示“接入正常”。

注意事项：

- Cookie 是登录凭据，只能用于本人或明确授权的账户，不要通过聊天、邮件或公开文档传递。
- 必须复制完整 cURL，而不是只复制 Request URL；完整请求中需要包含 Cookie、CSRF、aadvid 和当前签名参数。
- 程序从第一段自动得到列表查询参数、复制查询参数、Cookie 和 CSRF，从第二段得到更新查询参数并在内部生成系列、广告组和广告的开启、关闭模板。用户不需要再复制第三条请求。
- 为避免重复改变真实广告状态，接入检查不会重放启停请求；“接入正常”表示必要字段完整、账户读取成功，并且从真实启停 cURL 按已知接口契约生成了三级双向模板。后续真实操作失败会记录错误并把连接标为异常。
- 完整 cURL 可能包含 msToken 和签名参数，系统只在本机解码并使用 Windows DPAPI 加密，不会把这些内容明文写入 SQLite。
- 程序按全局轮询间隔检测账户连接；Cookie 失效会在用户管理标红。重新登录后从该账户的“接入”覆盖导入即可。
- 系统禁止把 Cookie 请求发送到非 TikTok 域名，并禁止自动跟随重定向。

## 3. TikTok Marketing API 接入

官方 API 适合长期稳定运行。当前版本支持手动填入长期 Access Token，后续可以增加浏览器 OAuth 授权。

1. 登录 TikTok for Business Developers，注册开发者并创建 Developer App。
2. 按实际功能申请 Campaign Management 和 Reporting 等权限，不要申请暂时不使用的权限。
3. 配置授权回调地址。桌面或本地模式可使用 TikTok 允许的 localhost 回调。
4. 让广告账户持有人打开授权链接并授权，使用 auth_code 换取长期 Access Token。
5. 记录授权响应中的 advertiser_ids，选择要管理的 advertiser ID。
6. 进入用户管理，点击目标账户后的“接入”，切换到 Marketing API，填写 advertiser ID 并保存。
7. 将 Access Token 填入凭据区域并加密保存。App Secret 不需要保存在本工具中。
8. 保存 Access Token 后，系统会自动通过官方 campaign/get 只读接口验证 Token 与广告账户权限。
9. 检测通过后执行检测，系统分页读取 campaign/get、adgroup/get、ad/get，并通过 report/integrated/get 读取当天消耗、转化、CPC、CPA 和 Shop 加购指标。
10. 官方状态写入使用 campaign/status/update、adgroup/status/update 和 ad/status/update。

注意事项：

- Access Token 的权限以广告主实际授权范围为准。
- 列表和报表均支持分页；报表字段仍受开发者应用权限和广告账户类型限制。
- 切勿把 App Secret、Access Token 写入代码、Git 或公开文档。

## 4. Cookie 与 API 自由切换

两种 Provider 的参数和凭据按账户独立保存，切换不会删除另一种接入配置。

1. 在用户管理中点击账户后的“接入”，分别完成 Cookie 和 Marketing API 配置及状态验证。
2. 点击该账户的“编辑”，在默认接入方式中选择当前要使用的 Provider。
3. 保存配置后，账户自动化和规则引擎会使用选中的 Provider。
4. 切换前先确认目标 Provider 状态为连接正常；未通过检测时不要开启真实自动执行。

注意事项：

- Provider 切换只改变该账户的数据和操作通道；九条全局规则不会改变。

## 5. 账户自动化开关

每个广告账户只保留一个自动化总开关；开启后默认按全局规则自动执行。

1. 进入用户管理，在目标账户一行点击“开启自动化”或“关闭自动化”。
2. 开启后，调度器按全局轮询间隔读取数据，命中已启用规则时直接执行真实启停。
3. 关闭后，调度器会跳过整个账户；接入凭据、规则和历史记录不会删除。
4. 新增账户默认开启自动化。正式接入前可先关闭，完成 cURL 或 API 接入后再开启。
5. 需要只看判断结果时使用自动化中心的“检测预览”，该操作不会写入广告状态。

注意事项：

- 账户总开关与单条规则开关是日常自动化的两个执行门控；不再设置独立能力开关或执行模式。

## 6. 规则配置

系统内置九条固定启停规则，全部接入账户共用；规则结构、优先级和动作锁定，只允许修改数值与单条启停状态。

1. 在规则配置顶部设置轮询间隔和单轮最多启停数；默认分别为 5 分钟和 15 个，修改后点击“保存运行设置”。
2. 系统固定只处理当前时间向前 48 小时内创建的推广系列；此保护范围不可修改，缺少创建时间的对象不会参与判断。
3. 推广系列、广告组和广告共用九条规则；推广系列默认不应用，广告组和广告默认应用。
4. 每条规则卡片只显示简洁含义、固定动作和可修改的红色数值；不能新增、删除或改变运算关系。
5. 需要暂停某条规则时关闭该卡片右上角开关；修改层级、数值或开关后点击“保存规则配置”。
6. 同一对象命中第一条有效规则后停止继续判断；命中开启规则时，手动关闭的对象也会被重新开启，但父广告组关闭时不会开启子广告。
7. 保存后建议先在自动化中心执行检测预览；确认结果后开启账户自动化，系统会按轮询计划直接执行。

注意事项：

- 规则数值全账户共用，但账户币种可能不同；混用币种时应使用适合全部账户的数值。
- 九条规则依次覆盖：单次转化 CPC 过高、单次转化 CPA 过高、单次转化达标恢复、多次转化 CPA 过高、多次转化达标恢复、零转化消耗过高、零转化 CPC 过高、有消耗无加购、有加购恢复。

## 7. 用户管理

用户管理中的每一行代表一个 TikTok 广告账户；凭据、Provider、启用状态和执行记录独立，九条规则与轮询配置全账户共用。

1. 点击新增账户，填写账户名称、类型和默认接入方式；账户时区和执行模式不需要填写。
2. 创建完成后点击该账户后的“接入”，导入 Cookie cURL 或填写官方 API 参数。
3. 新账户自动使用九条全局规则、5 分钟轮询间隔和单轮最多 15 个启停操作，但不会复制其他账户的 Cookie 或 Token。
4. 使用自动化开关可以让调度器跳过整个账户；重新开启不会丢失配置。
5. 用户管理每 30 秒刷新状态展示；后台按全局轮询间隔检测真实连接，Cookie 失败时会标注“Cookie 已失效”。

注意事项：

- 本页管理 TikTok 广告账户；本机员工登录账户和角色权限在系统权限页面管理。

## 8. 自动化中心

自动化中心负责检测预览、立即执行和记录真实启停结果。

1. 先确认左上角软件总开关处于运行中；关闭时全部后台检测和广告写入暂停。
2. 先点击检测预览。该操作会刷新真实数据并计算命中项，但永远不会修改广告状态。
3. 检测结束后查看“最近一次三层同步”：系列、广告组和广告数量均大于 0 且没有同步告警时，三层数据才会参与规则判断。
4. 点击立即执行会按当前规则直接执行真实启停；账户自动化关闭时不能运行。
5. 后台轮询与立即执行使用相同逻辑，并遵守 48 小时范围、层级适用、单轮上限、冷却时间和忽略名单。
6. 连续三次写入失败会熔断本轮，并把连接状态标记为异常。
7. 命中开启规则时，手动关闭的系列、广告组或广告也可能被重新开启。
8. 自动申诉、复制广告和删除广告卡片可先保存文案、命名与删除保护规则；标注执行器待接入的功能当前不会写入 TikTok。

注意事项：

- 桌面程序关闭后本地调度器不会运行；重新打开后会按轮询间隔继续。
- Cookie 写入缺少对应层级和方向的 cURL 模板时会安全失败，不会猜测接口。

## 9. 广告管理

广告管理展示最近一次检测到的系列、广告组和广告，可筛选、手动启停、加入忽略名单并查看操作记录。

1. 先完成一次检测，然后按名称、ID、层级或状态筛选对象。
2. 手动启停会弹出二次确认，并把操作结果写入本地记录。
3. 点击忽略并填写原因后，该对象不会参与自动化；取消忽略后恢复参与。
4. 广告层级可加入申诉队列，申诉原因和状态保存在本地操作记录。
5. 广告组可点击定时 / 过夜：单次定时在指定时间开启或关闭一次；每日过夜按设置的首次关闭和开启时间每天重复。
6. 账户自动化或软件总开关关闭、连接异常时，定时任务不会执行；执行结果和来源会写入广告操作记录。
7. 操作成功后程序会尝试重新检测；若 TikTok 状态传播有延迟，可稍后手动刷新。

注意事项：

- 申诉队列当前用于记录和人工跟进；没有真实申诉 API 或 cURL 模板时不会自动提交。
- 删除和复制属于高风险或结构性操作，未具备对应 Provider 模板时保持能力门控。

## 10. 广告分析

每次检测都会保存标准化指标快照，默认保留 90 天。

1. 选择今天、昨天、三天、七天或三十天；需要其他范围时使用开始和结束日历，自定义范围最多 90 天。
2. 选择广告系列或广告组层级，避免跨层级累计同一消耗。官方 API 接入还可选择广告层级。
3. 顶部显示最新批次的消耗、点击和转化汇总。
4. 趋势表按检测批次汇总对象数量、消耗、点击、转化、平均 CPC 和平均转化成本。
5. 批次数据透视位于检测批次趋势表上方，数据来源与趋势表完全相同；在一张组合图中选择消耗、点击或转化柱状指标，以及平均 CPC 或平均转化成本折线指标。
6. 结合自动化中心的决策记录判断规则是否过严或过松。

注意事项：

- Cookie 指标来自所导入列表请求的 row_data。系列、广告组和广告三层都同步成功时，可按实际返回字段分析；若广告层同步告警或没有返回指标，则不要据此作出广告层判断。官方 API 指标来自 report/integrated/get。
- 本地数据库默认只保留最近 90 天的指标快照。

## 11. 消息推送

消息推送是全局功能。邮箱、企业微信和飞书可同时启用；每次存在到期账户的实际轮询批次结束后，各渠道各发送一份账户汇总。

1. 进入“消息推送”，选择要使用的渠道。先保存参数和凭据，再点击“发送测试”；只有状态显示“已就绪”且渠道开关已开启时，渠道才参与自动推送。
2. 邮箱：在邮箱服务商后台开启 SMTP 并生成客户端授权码，填写服务器、端口、SSL/TLS、发件地址、收件地址、SMTP 用户名和授权码。服务商要求授权码时不要填写日常登录密码。
3. 企业微信：在目标企业微信群中添加群机器人，复制 Webhook，粘贴到企业微信卡片，按需开启提醒所有人，保存后发送测试消息。
4. 飞书：在目标群中添加自定义机器人，复制 Webhook；若机器人启用了签名校验，同时填写签名密钥，保存后发送测试消息。
5. 推送内容按账户统计开启数、关闭数、无操作、失败和跳过，并保留最近 90 天的轮询汇总与推送记录。没有到期账户的空调度不会产生消息。
6. 发送失败会进入本机重试队列，最多尝试 3 次；通知失败不会阻断或回滚已经完成的广告启停。
7. 更新配置后渠道会回到“待测试”状态。凭据输入框保持空白表示保留现有凭据；删除凭据后参数仍保留，但渠道不会继续发送。

相关官方文档：

- [Nodemailer SMTP 官方文档](https://nodemailer.com/smtp)
- [企业微信群机器人官方文档](https://developer.work.weixin.qq.com/document/path/91770)
- [飞书自定义机器人官方文档](https://open.feishu.cn/document/ukTMukTMukTM/ucTM5YjL3ETO24yNxkjN)

注意事项：

- SMTP 密码、授权码、企业微信 Webhook、飞书 Webhook 和签名密钥均由当前 Windows 用户的 DPAPI 加密，只在发送时解密，不会通过读取接口回显。
- Webhook 本身具有发送权限，应视为敏感凭据；不要写入代码、Git、公开文档或聊天记录。
- 消息推送只统计自动调度触发的 scheduler 轮询；手动预览和手动立即执行不会额外发送轮询汇总。

## 12. 本机登录与权限

登录账户与 TikTok 广告账户相互独立。开发者、管理员、操作员和只读用户由服务端权限控制。

1. 首次启动创建开发者账户后进入系统权限，可新增本机登录账户。不要多人共用开发者密码。
2. 开发者拥有全部权限；管理员可管理系统与用户；操作员可接入账户、执行自动化和广告操作；只读用户只能查看。
3. 停用用户会立即删除该用户全部登录会话；系统至少保留一个启用的开发者账户。
4. 在修改我的密码中输入当前密码和新密码。修改成功后所有会话失效，需要使用新密码重新登录。
5. 本地 API 写操作要求有效会话、CSRF 安全令牌和对应角色权限，不能只依赖页面隐藏按钮。

注意事项：

- 密码只保存 scrypt 加盐哈希，不保存可解密明文；Cookie、Token 和通知凭据仍由 Windows DPAPI 加密。
- 忘记唯一开发者密码时不能从数据库还原密码，需要使用受控的本地恢复流程，避免设置通用后门密码。

## 13. 相同广告多账户投放

创建广告页面使用广告预设统一管理地区、预算、出价和时间；Excel/CSV 仅填写推广系列、广告组、视频代码和产品 URL。单账户和多账户都是从零新建；多账户发布时，同一视频代码由每个目标账户在自己的素材库中分别解析和引用。

1. 确认每个要发布的账户均已完成两条 Cookie cURL 接入，且状态显示为接入正常。
2. 选择“单账户批量创建”后选择一个创建账户；选择“多账户同时发布”后勾选一个或多个目标账户。每个账户都会从零新建系列、广告组和广告。
3. 选择表格批量导入，点击下载模板与填写规范。模板的批量创建工作表用于导入，填写示例和填写规范工作表仅供参考。
4. 先在广告预设模板中设置投放地区、广告组日预算、出价、创建/结束时间和初始状态；这些配置会统一应用到本次导入的每一行。
5. 导入表只保留四列：推广系列名称、广告组名称、视频代码、产品 URL。产品 URL 必须以 http:// 或 https:// 开头。
6. 广告名称不需要填写，软件会在保存计划时统一生成 YYMMDD:XXX，例如 260716:001；同一天的不同计划会自动顺延编号。
7. 导入 .xlsx 或 .csv 后检查逐行错误和前 100 条预览；单次最多导入 500 条，存在错误时不能保存。
8. 校验通过后点击保存批量投放计划。按钮会显示任务条数 × 目标账户数，目标账户无需在表格中重复填写。
9. 预设是计划的唯一配置来源：保存时系统会再次覆盖地区、预算、出价、时间及初始状态，避免导入数据与预设不一致。
10. 点击“创建并发布”或“向所选账户发布”。系统会立即执行创建，并在计划列表中显示每个账户的执行结果。
11. 视频代码必须可由每一个目标账户自己的素材库使用；如某个账户没有对应视频或授权，该账户会失败，其他账户不受影响。不要填写或迁移其他账户的素材 ID。
12. Cookie 接入只需导入 /adgroup/list/? 与 /ad/update_status/? 两条 cURL。创建链路使用该目标账户已接入的会话；若 TikTok 拒绝会话、签名或必填参数，系统会停止该账户并显示错误摘要。

注意事项：

- Cookie 创建路径只依赖已导入的两条接入 cURL 所保存的目标账户会话；不要额外导入、粘贴或保存创建 cURL。
- 表格不要保存 Cookie、Access Token、密码或 Webhook；这些敏感凭据只在账户接入页加密保存。
- 表格中的创建时间由预设统一控制；TikTok 拒绝会话、签名或必填参数时，该账户不会创建，并会保留错误结果供处理。

## 14. 常见问题

优先根据连接状态和提示定位问题，不要反复提交真实广告操作。

1. Cookie 返回 HTTP 401/403：重新登录、确认 Cookie 来自同一账户，并检查 CSRF Token。
2. Cookie 返回 HTML：复制的是网页地址而不是 Fetch/XHR JSON 请求 URL。
3. 连接超时：确认本机可访问 TikTok，检查代理网络，并重试一次。
4. 提示 fetch failed：本地 API 会自动继承 HTTPS_PROXY/HTTP_PROXY 或 Windows 系统代理；确认 QuickQ、Clash 等代理仍在运行，然后重启本地 API 再检测。
5. API 返回授权错误：核对 advertiser ID、Token 权限和广告主授权状态。
6. 同步数量为 0：检查列表 URL 的分页、筛选参数和响应字段，查看页面中的同步警告。
7. 凭据无法解密：凭据由当前 Windows 用户保护，换电脑或换系统用户后需要重新保存。

## 15. 新功能教程更新规则

本手册是产品功能的一部分，每次新增用户可见功能必须同步更新。

1. 在 packages/manual/guide.json 新增或更新对应章节。
2. 章节必须包含使用前提、具体步骤、风险提示和常见错误。
3. 执行 pnpm docs:generate，更新 docs/USER_GUIDE.md。
4. 增加功能测试，并在浏览器验证手册入口和新功能入口。
5. 代码评审时检查教程是否与当前页面字段和按钮名称一致。

注意事项：

- 不得只更新 Markdown；Web 置顶手册和 Markdown 必须来自同一份 guide.json。
