# 人工操作与真实环境验证台账

本文件记录开发路线中无法由自动化测试安全替代的操作。未满足对应放行条件前，开发和测试不得调用真实 TikTok 写接口。

## 操作等级

- `人工确认`：必须由产品负责人明确批准范围和风险后执行。
- `可辅助`：可使用 computer use 辅助点击或采集结果，但不得代替人工确认、密码、2FA 或权限授权。
- `禁止自动`：Codex、脚本和后台任务均不得自行执行。
- `离线完成`：可通过模拟 Provider、数据库和 UI 测试完成。

## computer use 可辅助的范围

允许：

- 打开 TikTok 后台指定页面并截取可见结果。
- 帮助定位 Network 请求、导出 HAR 或读取非敏感状态。
- 在用户已明确批准后，辅助填写测试表单；提交真实写操作前仍须再次人工确认。
- 核对创建后的系列、广告组和广告是否存在，以及开关是否全部关闭。

禁止：

- 代替用户输入密码、Cookie、Token、2FA 或支付信息。
- 自行点击发布、开启、删除、预算修改、申诉等真实写操作。
- 绕过软件总开关、账户 `manual-approval` 或 Provider 熔断。
- 把 HAR、cURL、Cookie、Token、凭据或运行数据库加入 Git。

## 安全积压项

- 数据库迁移备份目前每次打开已有数据库都会创建；后续阶段 H 需要改为一致性快照、保留策略和恢复 UI。
- 用户手册需在阶段 A/C 的用户流程稳定后统一更新，避免在安全状态机仍变化时反复生成。
- 未跟踪的必要生产源码在获得提交批准时必须显式纳入；运行数据和私有目录永远不得纳入。

## 阶段 C 真实只读验收（暂缓）

- 当前处理：已完成离线 Provider、分页、指标、契约漂移、过期状态和自动写入拦截测试；未连接真实 TikTok 账户。
- 必须人工核验：账户当天数据范围、完整分页、CPA/CPC/转化/加购指标、币种及 TikTok 页面总数。
- 可由 computer use 辅助：打开只读报表并截图、导出不含凭据的统计结果、对照软件同步摘要。
- 放行条件：用户明确批准只读核验；账户保持 `manual-approval`；不得执行启停、创建、复制、删除或申诉。
- 记录要求：账户名称、核验时间、Provider 类型、页面总数、软件计数、覆盖日期、缺失指标和契约版本。不得记录 Cookie、Token 或完整 cURL。
